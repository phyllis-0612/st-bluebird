# 青鸟 · Bluebird v0.6.1

署名：克克姐&奶盖&鱼仔

SillyTavern 小手机扩展：角色在剧情里主动给你发消息，手机里聊过的内容自然回到剧情。

## 当前进度：第六段后修正 · 用户手机归属

已做：

- 主线生成前注入手机规则和在场名单；角色卡联系人可主动来信，群聊使用未停用成员
- 主动消息开关、克制/正常/黏人三档、默认 3 楼冷却与两种规则位置
- 青鸟入口：默认可拖动的悬浮球，可切换为收进酒馆魔法棒菜单，显示当前聊天的未读数
- 手机全屏面板，适配动态视口高度与四边安全区；打开时隔离背后的酒馆控件，关闭时恢复
- 消息列表与会话页；文字、语音文字版、图片描述、转账、位置五种消息；通讯录可从绑定世界书提取
- 从楼层原文读取消息，当前 `mes` 为准；删除楼层、编辑、切 swipe 后重建，不另存手机消息副本
- 点击正文提醒直达会话；会话中的楼层分隔条返回酒馆原楼层
- 转账收款与退还写回原文和当前 swipe，随后交给酒馆保存；不允许重复处理
- 按稳定楼层和 swipe 标识记已读，删除其他楼层或其他 swipe 不会令原消息变成未读
- 配色：跟随系统、日间、夜间三种，颜色是插件自己的，不跟酒馆主题
- 设置页：正文提醒可切换，隐藏提醒不删除消息；忽略的思考标签可配置
- 扩展抽屉里：启用开关、入口显示方式、打开青鸟；青鸟面板的设置页也能切换入口

语音播放和青鸟独立 API 预设已开放，真实 iOS 播放与不同接口的跨域表现仍需实测。图片发送画面描述，语音发送文字，不自动生成图片。

## v0.6.1 用户手机归属

- 主线规则明确青鸟只属于用户：新生成的用户来信使用 `<bb-phone to="我">`。角色与朋友之间仍能聊天，写入剧情正文并影响后续发展，不转入用户手机。
- 明确标为其他人收件的消息不会进入青鸟，也不计入用户来信冷却；旧存档没有收件人标记的消息继续按原格式读取。

## v0.6.0 语音播放与 API 预设

- 手机语音条点击后显示文字；为该联系人指定 MiniMax 或 ElevenLabs 音色且存在 Key 时，会合成并播放。没有配置时仍能展开文字，语音模式关闭时直接显示文字。
- 青鸟设置新增 API 预设：默认跟随酒馆，也可新建、复制、删除 OpenAI 兼容预设，填地址、Key 和模型 ID；只影响青鸟的手机回复和 NPC 提取，不切换酒馆主线模型。支持从预设接口获取模型列表。
- 通讯录逐人选择语音服务与音色，可从账号获取音色，也可手填 voice_id。每次使用时优先读取梨园现有 MiniMax / ElevenLabs Key 与语音配置；梨园没填时使用青鸟设置里的值，不复制梨园 Key。
- 音频按服务、接口、账号、文本、音色、模型、语速和情绪散列后存在 IndexedDB；默认最多 200 MB，按最久未用清理。浏览器不支持时仍可播放，但不缓存。一次只播放一条。

见 [第六段语音实测](docs/testing-phase6.md)。

## v0.5.2 中文标签与状态栏选择

- 思考、状态栏和正文标签接受中文；思考栏可输入 `灵魂疏理` 或 `<灵魂疏理>`，保存后按对应标签过滤。
- 设置页扫描当前聊天所有正在显示的楼层原文，列出成对标签，勾选后排除该标签块，不带给手机回复模型。手动填写仍可用。旧标签设置保留。

## v0.5.1 加载修复

修复世界书模块引用路径，避免扩展在初始化前加载失败。

## v0.5.0 NPC 通讯录

- 从当前角色卡的主世界书和附加世界书分批提取人物候选；地点、组织等可能不是人物的候选默认不勾。检查后点「加入通讯录」。提取调用酒馆当前模型，设置了手机模型时复用该模型。
- 通讯录保存名字、来源书名及条目 UID、主动程度，不存世界书正文；手机回复每次重新读取最新条目。通讯录中可逐人修改主动程度，声音设置入口留到第六段。
- NPC 手机回复只带 `bb-present` 标注为在场的近期剧情；未标注楼层继承上一条在场名单，未知不算在场。不读取结绳全局总结。手机中直接告诉 NPC 的消息仍属于该会话记录。
- 主线规则列出全部角色卡和已选 NPC 联系人及逐人主动程度，发送人必须使用通讯录原名。

实测步骤见 [第五段 NPC 实测](docs/testing-phase5.md)。实际 1.19 连接、世界书较多时的分批效果以及手机剧情知情情况仍需在酒馆检查；本段确认后再进入第六段。

## v0.4.1 调整手机回复触发方式

- 现在点「发送」只把每条消息保存到当前聊天，连续发送不调用模型。会话底部显示待回复条数，点「让对方回复」才发起一次请求，模型同时看到刚才发的所有消息。
- 请求失败时仍可点「重试回复」，无需重发；刷新后待回复消息和按钮仍在。正在生成回复期间暂时锁定输入，避免后来的消息被误认为这次请求的一部分。
- 移除失效的「连发等待」设置。旧设置留在存档中也不会再触发自动回复。

## v0.4.0 更新

- 开放手机输入；从通讯录也能直接开始聊天。文字、语音文字、转账、图片描述、定位均可发送。
- 手机消息单条保存，点击「让对方回复」时才用酒馆当前连接和 `generateRaw` 独立回复，不套主线提示词预设。显示输入状态，失败可重试，未发送的草稿在刷新会话时保留。
- 手机回复使用角色卡人设、结绳当前有效总结与脉络、实际未隐藏剧情和该会话最近 30 条记录。没有有效总结时使用可配置的近期剧情，默认 20 楼。正式结绳只读接口仍在青鸟后续完成后添加。
- 手机消息先保存到当前聊天暂存区。主线生成时注入本轮快照，成功后写入新回复的前一楼，与清空这批暂存一起保存。取消、失败、目标编辑或切版本时保留暂存；后续新发消息不被提前清空。
- 手机回复任务绑定当前聊天；切聊天、编辑、删楼、切 swipe 或开始主线后，旧结果不会写入新状态。刷新后未回复的消息可手动重试。
- 手机模型留空时跟随当前连接；要用 Flash，在设置里填写当前连接支持的准确模型 ID。独立模型只适用于聊天补全连接，仅修改带手机标记的那次请求，不改变酒馆主线模型、key 或连接设置。
- 新增手机上下文长度、回复长度、正文和状态栏标签设置。真实声音播放仍留给第六段。

已通过 57 项自动检查和 JavaScript 语法检查。DOM 替身验证了输入、草稿、附件和状态交互；当前环境没有浏览器程序，未验证真实手机布局、iOS 键盘、酒馆实际 API 返回与保存。详见 [第四段手机实测](docs/testing-phase4.md)。本段实测通过后再进入第五段。

## v0.3.0 更新

- 完成第三段规则注入：用酒馆生成拦截器，在新用户消息入楼、重写目标移除后读取原文计算冷却；不新建 AI 请求。
- 角色不在你身边时按主动程度发送消息，回复末尾记录在场名单；关闭主动消息后仍记录在场。通讯录显示当前角色卡联系人。
- 默认两轮主动来信之间间隔 3 楼，用户和隐藏楼层也计数；只认当前原文中有效的主线来信，手机来源、思考和代码示例不重置冷却。
- 切换聊天、停用、后台 quiet、代写用户和预演清理旧注入；滑动重写排除被替换回复，续写不新开消息块。
- 冷却和同场禁止由生成规则约束，模型遵守率需使用常用预设实测；本段不会自动删改模型违规生成的原文。

实测步骤见 [第三段手机实测](docs/testing-phase3.md)。实测通过后继续第四段。

## v0.2.0 更新

## 从仓库安装（推荐）

在酒馆的「扩展 → 安装扩展」中填入：

```text
https://github.com/phyllis-0612/st-bluebird
```

安装后刷新酒馆，默认在屏幕右下区域显示青鸟悬浮球。可在设置里切换为魔法棒菜单入口。已有插件时点击扩展更新，再刷新，无须卸载或删除设置。第三段随主线回复生成手机消息，使用酒馆已有模型和预设；可在青鸟设置关闭主动消息。

## 手动安装

把整个 `st-bluebird` 目录放进：

```
SillyTavern/public/scripts/extensions/third-party/st-bluebird/
```

已有旧版本时覆盖插件文件，然后刷新。无须删除原设置。

## 给奶盖：需要真机确认的地方

1. 悬浮球点击、拖动、位置记忆与屏幕旋转；切到魔法棒后只在魔法棒菜单显示入口，输入栏不新增一行。
2. 目标酒馆版本的 `SillyTavern.getContext()` 字段：`extensionSettings`、`saveSettingsDebounced`、`eventSource`、`eventTypes` 或 `event_types`、`characters`、`characterId`、`groups`、`groupId`。
3. 手机全屏时 `z-index: 9000` 能不能压住酒馆顶栏和各个抽屉。
4. 酒馆全局样式或美化主题有没有压过面板里的按钮、单选、开关。面板样式都以 `#bluebird-panel` 开头，理论上压得住。
5. iOS 刘海和底部横条：全屏时用了 safe-area，确认内容不被挡。

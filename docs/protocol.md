# 青鸟消息协议 · v0.4.1

消息原文是唯一数据来源，存放在酒馆楼层的 `mes`，跟随当前 swipe。第二段只读取、展示与改写转账状态，不调用生成 API。

## 主线写入

```text
<bb-phone>
陆知行|text|到家没
陆知行|voice|外面下雨了，你别走那条巷子|温柔
陆知行|image|车窗上全是雨，雨刷停着
陆知行|transfer|200|打车钱
陆知行|location|城南便利店|等雨小一点
</bb-phone>
<bb-present>陆知行,周屿</bb-present>
```

一楼可有多个手机块，一个块可有多个发送人。发送人的名字确定一对一会话，角色名需保持一致。`members` 在内部为数组，后续再接通讯录与群聊。

`voice` 最后一个字段可记录情绪。第二段开启「语音消息模式」时显示播放图标，点击展开文字；关闭时直接显示文字。第六段再接入声音播放。`image` 是画面描述。转账金额为正数、至多两位小数；状态为 `accepted` 或 `returned`：

```text
陆知行|transfer|200|打车钱|accepted
陆知行|transfer|200||returned
```

没有备注时也支持 `陆知行|transfer|200|accepted`；写回时统一为五个字段。已有状态的转账不能再次收款或退还。

## 手机主动聊天归属

```text
<bb-phone source="phone" chat="陆知行">
我|text|我到家了
陆知行|text|那就好
</bb-phone>
```

发送人为「我」时必须注明 `chat`，否则跳过这一行，不能猜测收件人。第五段固定联系人 ID 接入后，可加 `chat-id="联系人ID"`；显示仍使用 `chat` 名称。名字与 ID 分开，可以兼容重名或改名。

## 转义

| 内容 | 存档中的写法 |
| --- | --- |
| 换行 | `\n` |
| 回车 | `\r` |
| 竖线 | `\|` |
| 反斜杠 | `\\` |

例如 `我|text|第一行\n第二行，A\|B`。用户表单输入由插件序列化，AI 规则需要说明转义。未知转义保留为原文，不吞掉路径中的反斜杠。

## 思考与在场名单

- 默认忽略 `think`、`thinking`、`analysis`、`reasoning`，设置里可以更改。未闭合的思考块从开始位置一直忽略到末尾。
- Markdown 围栏代码中的标签视为示例，不作为消息读取。实测时向楼层粘贴纯标签，不带代码围栏。
- 解析时屏蔽内容保持原文长度，消息始终保存原文偏移；不使用过滤后的行号写回。
- 没写 `bb-present` 时沿用最近记录；「无」表示明确无人，「未知」或空名单表示未知。界面说明这是最近记录，不能保证角色当前仍在场。
- 在场标签从显示和发给主线的提示词中移除，手机消息保留在主线上下文中。

## 数据与身份

- 手机消息的内容、类型和转账状态只存楼层文本。
- 楼层 `extra.bluebird` 保存稳定 `floorId` 和 `swipeId`；各 `swipe_info` 保存对应身份，以兼容酒馆切 swipe 时替换 `extra`。这是定位元数据，不是消息副本。
- 已读保存在当前聊天 `chat_metadata.bluebird.lastSeen`，按会话记录已读消息身份。身份结合楼层、版本、消息内容与重复序号；转账状态变化不制造新消息。
- 删掉前面的其他楼层、插入不同内容的消息、删除其他 swipe 后，原消息仍能对应已读位置。编辑消息内容会视为新消息；完全相同的重复消息通过顺序区分。
- 对结绳隐藏的楼层，手机记录仍解析；只在第四段构造回复提示词时过滤隐藏剧情原文。
- 保存、显示刷新使用酒馆接口。写回前检查当前聊天并重新解析；不接受不存在的目标、重复转账或生成中的操作。保存接口若抛出错误，只撤销仍属于这次操作的修改。部分酒馆版本会在内部处理保存错误，真实保存结果需依照酒馆提示并刷新确认。

## 后续施工约定

第四段开始生成前固定本轮暂存快照、目标聊天和前一楼的版本。只有正常完成且成功保存后才移除这批暂存；后续新发的消息不在这批里。暂存消息全量保留，30 条只是回复上下文长度，不能拿来裁剪未落楼消息。手动请求的后台回复同样绑定原聊天。

第四段回复记忆默认使用「人设 + 结绳当前有效总结与脉络 + 实际未隐藏剧情 + 当前手机会话及暂存」。无结绳时退回可配置的近期剧情。NPC 不直接获得整份全局总结，知情范围另行处理。调用酒馆当前 API 不代表自动切换到 Flash，独立模型选择需明确配置。

青鸟后续功能完成后再给结绳增加只读接口。世界书模式和注入模式均需读取当前有效记忆；删楼回退或版本切换尚未处理完成时不能使用过期结果。

## 第三段生成规则

青鸟通过 manifest 的 `generate_interceptor` 接入主线生成，用 `setExtensionPrompt` 在聊天位置注入 SYSTEM 规则（默认深度 0，可选 1，不参与世界书扫描）。只读取原聊天，未修改传入模型的聊天数组。quiet、impersonate、预演不注入主动规则。

冷却从最近一个有效主线来信楼层开始，计算其后实际楼层数，包含用户楼层和隐藏楼层；`source="phone"` 不重置冷却。swipe 排除目标旧回复，regenerate 使用酒馆已移除目标后的原聊天，continue 不新开手机消息块。规则准备或生成失败不会写入额外冷却状态。

当前角色卡与群聊未停用成员为联系人。场景名单按实际剧情写入 `bb-present`，消息内容只在 `bb-phone` 中出现。同场和冷却是模型提示规则，违规输出保留原文，需要实测检查遵守情况。

## 第四段存储与请求

暂存记录为 `chat_metadata.bluebird.pending` 数组，每条记录保存 `id`、`chatName`、`fields`、`createdAt`。这些记录跟当前聊天保存，不在扩展设置里存副本。回复上下文最多 30 条，落楼注入始终使用本轮全部有效暂存，不裁剪未落楼消息。

生成拦截器在 normal、regenerate、swipe 时捕获暂存、目标聊天和前一楼原文/版本。quiet、continue 和用户代写不落楼；预演不会运行酒馆拦截器。只有成功来信事件和生成结束事件均出现后才落楼，识别流式停止与失败，不凭停止按钮隐藏判定成功。

落楼写入 `<bb-phone source="phone" chat="联系人">`，同步当前 `mes` 和 `swipes[swipe_id]`。文本写入与本批暂存移除使用同一次保存；失败时保留暂存。目标被编辑、删除、切版本或换聊天时放弃此次落楼，留待后续生成。落楼后的消息继续跟随原楼层文本。暂存转账可处理，其状态也随落楼写入。

属性值使用 HTML 实体保护引号和尖括号；字段增加 `\u003c`、`\u003e` 的尖括号转义，避免用户输入的闭合标签截断消息块。解析还原为原文字。

手机回复使用 `generateRaw({ prompt, systemPrompt, trimNames: false, responseLength })`。独立模型用 `CHAT_COMPLETION_SETTINGS_READY` 精确匹配该请求的唯一标记后修改请求 model，结束后移除钩子；不改全局模型设置。底层仍使用当前连接的采样和兼容参数，异构模型的上游支持需实测。

结绳适配只读取当前 metadata 的有效段落与对应脉络，或绑定世界书中当前聊天、当前总结类型的活动条目；不读取备份，不修改结绳。正式公开只读接口尚未添加，因此结绳回退/切版本后的同步仍需真机确认。

手机端「发送」只保存暂存，不触发 API；显式点「让对方回复」后才将该会话最新多条消息一起交给 `generateRaw`。

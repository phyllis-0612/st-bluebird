# 第三段 · 角色主动发（v0.3.0）

在酒馆扩展页更新青鸟并刷新，在青鸟设置底部确认版本为 0.3.0。不用卸载或清空旧记录。

## 默认设置

- 角色主动发消息：开启。
- 主动程度：正常。
- 冷却：3 楼。两次主线来信之间至少隔 3 个现有楼层，用户消息也计一楼；结绳隐藏的楼层仍计入。比如第 5 楼收到消息，第 6、7、8 楼之后，下一次回复才允许再发。
- 规则位置：靠近最新消息（深度 0）；不遵守时可试「提前一楼」（深度 1）。
- 当前只使用角色卡联系人；群聊使用未停用的角色成员。NPC 提取在第五段，手机输入在第四段。

规则随正常主线生成注入，使用你现有的模型与预设，不单独发请求。模型负责决定是否发消息；冷却与同场禁止通过提示词约束，遵守情况需要实测，不保证每次生成都遵守。

## 手机实测

1. **离场且有理由**：安排角色在别处，让他有确认到家、提醒带伞等具体理由。继续剧情，看正文是否有消息提醒，青鸟会话是否收到消息。为快速测试可临时改为黏人、冷却 0，测试后改回默认。
2. **同场**：让角色来到你面前，继续剧情。即使设为黏人，也不应发手机消息。打开已有会话，顶部应显示「最近记录：与你同场」。没有人在场时，回复原文末尾应为 `<bb-present>无</bb-present>`。
3. **冷却**：设为 3，在收到一轮来信后继续剧情。在它后面尚不足 3 楼时，生成规则要求不发；用户和 AI 各一条算两楼。同一回复内多条消息算同一轮。手机聊天的 `source="phone"` 块不重置主动消息冷却。
4. **开关与三档**：关闭主动消息，应继续记录在场名单而不发来新消息；旧记录仍可阅读。再次开启生效。克制有确切理由才发，正常有合适时机就发，黏人更常主动找你，但不绕过同场和冷却限制。
5. **重写与聊天切换**：滑动重写有来信的回复时，旧版本的来信不应阻止这一楼重写出新来信；regenerate 按删除旧回复后的历史算。续写不新增来信块，可补完原有未闭合标签。换角色后通讯录和规则使用新角色，不沿用上一聊天的冷却。
6. **格式与思考**：检查楼层原文，标签应在实际回复末尾、思考标签之外。思考和代码示例中的标签、缺失或无效标签不会生成伪消息。缺少在场标签时会话保留最近已知记录，不当作当前同场。
7. **预设比较**：用常用预设分别测试两个规则位置。如果同场仍发、冷却仍发或不写标签，保留违规回复原文、当时的楼数及设置，便于调整规则。提示词预演、quiet 后台任务、代写用户消息不会注入主动消息规则。

## 本地已验证

生成前的联系人、字段转义、冷却边界、思考排除、swipe/编辑/删除、设置迁移、后台生成隔离、聊天切换过滤，以及原有消息和转账测试。

本地 DOM 替身不能验证真实浏览器布局或模型遵守率，需要以上手机酒馆测试。第三段实测通过后继续第四段。
